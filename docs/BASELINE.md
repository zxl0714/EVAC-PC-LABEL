## 创建和检查源码快照

在合集源码根目录运行，备份位置必须是原工程之外的新目录：

```powershell
py -3.12 scripts/snapshot_sources.py <原工程目录> <新备份目录>
py -3.12 scripts/snapshot_sources.py <备份目录> --verify
py -3.12 -m unittest discover -s tests -v
```

快照包含 Git 跟踪文件、未忽略的新文件、已删除文件列表、相对 HEAD 的二进制补丁、依赖 gitlink 固定提交和逐文件清单。修改过但未提交的文件按当前内容复制，复制前后再次核对原文件及工作树身份；检测到变化时保留现场并报告失败，不把不一致副本标成成功。

工具不覆盖已有目标，不改原工程，不复制忽略的 ROM、工具安装、缓存、存档或依赖 checkout 正文。恢复时先将 source 内容放入一个新工作目录，依据 snapshot.json 的依赖提交恢复开源依赖，再与原仓库历史对照；不要直接覆盖个人工作树。

## 验收基线

G2 的源码审计、37 项 Python 回归和 4 组原生测试通过。现有宿主源码、配套二进制与最后一次成功构建收据一致；这证明当前运行的程序对应已记录的维护源码，不证明全部游戏流程可玩。

实际 G2 基线从 Black Label／Seseri 的第一关、保存录像和局末返回开始。录像结束返回曾在缺失主程序回调处崩溃，函数声明已修订，需用真实回放验收。其他模式、重复切换、实体输入及音画分别登记，不以静态装载替代。

虫姬二的音频调度、DLC 与保存，以及绊地狱的保存事务、ATRAC9、资源覆盖和社区待传列入迁移保护范围。绊地狱偶发音画卡顿与不完整退出清理仍保持未完成，不因建立合集关闭问题。
