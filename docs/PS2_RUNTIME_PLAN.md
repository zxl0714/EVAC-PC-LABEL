# v0.9.0：PS2 运行时、ESPGaluda 与 Ibara

状态：实施中，当前推进首作静态重编译与运行时链接。实施顺序为 **运行时最小闭环 → ESPGaluda → Ibara → 合集交付**。

## 当前进展

- 项目锁定工具链已编译 PS2 分析／重编译工具、初始共用运行时、IOP 和窗口／音频依赖；没有沿用上游强制 AVX2、快速浮点或本机 CPU 优化选项。完整玩家构建认证仍待接入。
- 两作镜像已读盘确认：ESPGaluda `SLPS-25352`，4,073,586,688 字节；Ibara `SLPM-66301`，3,932,848,128 字节。启动程序均为入口 `0x00100008` 的 R5900 ELF，已记录摘要和资源 LBA。ESPGaluda 使用 CRI／EZMIDI 等 IOP 模块，Ibara 使用 MTS 系列模块，不能共用另一游戏的模块映射。
- ESPGaluda 的扁平 RWX 段混有代码与数据，快速函数扫描生成了错误指令。改用 Ghidra 的 PS2 分析和函数边界后，本轮生成零未处理指令／零错误；间接入口和实际执行路径尚待宿主验证。
- 首次读盘已通过。已修复 EE 优先级 0 被拒绝、优先级修改未返回原值的两处内核问题；新增无 ROM 回归覆盖线程描述符、优先级范围和临界区恢复。下一步接入光盘中 ARCADE／ARRANGE 两份重叠地址程序的静态重编译。
- 已盘点 17 份动态加载程序，包含两种模式、各关卡、结局及画廊。共用运行时已有按原始模块头选择静态代码、切换时交回调度器的机制回归；两种模式主程序已生成代码，实际菜单／进关仍待验收。ISO 准备工具会校验并提取这些分析输入，原始镜像保持只读。
- 17 个程序均已完成分析和代码生成，零未处理指令／零生成错误。已补齐关卡构建／注册工具，以及手柄连接时键盘仍可用的输入回归；当前正在首次编译完整模式宿主。
- 已实现全部作品的基础数据检查与灰色封面缓存，保留原卡片选择／导入／启动行为；共同机制、真实绘制及隐藏窗口交互回归通过，实际界面短验收待后续统一进行。

## 版本目标

新增共享 PS2 运行时，支持《エスプガルーダ / ESPGaluda》和《鋳薔薇 / Ibara》的 PS2 版本。两款游戏共用平台服务、图形和声音实现，各自保存数据版本、重编译配置及必要的游戏适配。

沿用现有启动器、`user-data/config.ini`、键盘／SDL 手柄、窗口预设、日志及打包流程。现有 Xbox 360／PS4 数据目录和已发布版本保持原样。

v0.9.0 另有覆盖全部作品的 [启动器封面布局计划](LAUNCHER_COVERS_PLAN.md)：默认保留当前横幅布局，新界面由配置手动开启并先内部验收。两种界面复用本计划的数据识别和启动接入。

## 运行路线

推荐以 [PS2Recomp](https://github.com/ran-j/PS2Recomp) 的 R5900 静态重编译工具为起点，将游戏主程序编译成 Windows x64 代码，再链接项目内的 PS2 专用运行时。该上游目前仍属实验阶段，不能将“工具编译通过”等同于游戏已经可玩。

[Waffle565 的运行时分支](https://github.com/Waffle565/God-Of-War-Native-Port/tree/runtime)提供了原生 GS、VU／IOP 代码生成及音频／系统服务的候选实现。先审查它们与《战神》专用适配的边界，再选取可复用部分；本项目不会继承另一游戏的硬编码地址、资源布局或性能结论。[PCSX2](https://github.com/PCSX2/pcsx2) 用作行为对照，以及图形、向量和声音实现的参考。

正式运行由本项目的游戏宿主执行静态重编译代码。通用 EE 解释器或动态重编译器可以帮助开发对照，不作为正式游戏主循环；也不以调用 PCSX2 可执行文件代替移植。VU／IOP 若暂时保留兼容执行路径，须记录其实际用途和成本，再决定是否转成原生实现。

优先直接加载游戏 ELF，使用宿主服务实现其所需的内核接口；目标是不要求玩家另外安装模拟器、配置 PS2 BIOS 或编译程序。是否能完成这一点，要在第一阶段用实际启动链验证。

## 统一工具链（本版约束）

PS2 构建使用项目同一套受版本锁定和校验的工具链。当前 `tools/packages.lock.json` 为 LLVM 23.1.3、CMake 4.2.3、Ninja 1.11.0，宿主 SDK 环境由现有 `Build-Common.ps1` 初始化 VS 2022 C++ Build Tools／Windows SDK。

- [ ] PS2 分析／重编译工具、共用运行时、第三方依赖及生成的两作 C++ 代码均从现有工具入口取编译器与构建工具。按目标 ABI 选择 `clang++` 或同一 LLVM 包中的 `clang-cl` 驱动，保持项目现有 CRT、优化、符号和最低 CPU 约定。
- [ ] 将上游 MSVC 专用代码、内联汇编、内建函数及 CMake 判断适配到这套工具链；检查实际 CMake 缓存、编译与链接命令，防止子项目悄悄改用 PATH 中另一份工具。
- [ ] 专用分析／代码生成程序作为固定版本的项目依赖恢复或构建。统一使用现有 Prepare／Build／Test／Package 入口；PS2 内部脚本可以分层，玩家和开发者不需要另进外部工程、打开 VS 解决方案或手动拼接库文件。
- [ ] 将 PS2 依赖、代码生成输入、工具摘要、编译选项、EXE／DLL 和 PDB 纳入现有构建认证体系。新增平台不能绕过相同源码提交、依赖恢复和产物配套检查。
- [ ] 在新 checkout 验证两条流程：不提供 ROM 时构建运行时／分析工具／机制测试；提供受支持 ISO 后完成生成、游戏构建、整理与组包。清除旧缓存后也应使用相同工具路径和版本，不依赖本机旧项目产物。

## 首批数据版本与玩家流程

首批候选为日版 ESPGaluda `SLPS-25352`、Ibara `SLPM-66301`。序列号已在 PCSX2 游戏数据库中核对；最终支持范围以拿到镜像后的启动 ELF、大小及 SHA-256 为准，不仅凭文件名或序列号放行。

玩家在对应目录放入一份 ISO，保留原文件名即可：

```text
game-data/
  espgaluda/
    README.txt
    <original-name>.iso
  ibara/
    README.txt
    <original-name>.iso
```

也可沿用“游戏数据…”选择现有外部目录。只拥有其中一款时可独立启动；目录里存在多个候选镜像时明确提示选择，不静默挑一个。

启动器读取镜像内的 `SYSTEM.CNF`、启动 ELF 和资源清单，自动完成必要准备。缓存复用现有 `cache/<game>/`、`prepared/<game>/` 的分工，存档使用既有 `user-data/<game>/` 体系，日志使用 `logs/<game>/`。原镜像只读，玩家无需手动解包、寻找 header 或提供生成文件；PS2 不复用 Xbox 360 的 ISO 提取工具。

当前数据指南中“ISO 先提取”的总说明，需要改为按平台区分，避免与 PS2 新流程冲突。PS2 首版先接受 ISO，其他镜像压缩格式不扩大本轮范围。

## 启动器：缺少数据的游戏置灰

此项覆盖全部 Xbox 360、PS4、PS2 作品。

- [ ] 未找到相关游戏数据时，banner 降为灰色，卡片文字和背景适度降低亮度；标题仍清晰可读，选中边框仍可辨认。
- [ ] 卡片继续支持点击和键盘选择，“游戏数据…”入口可用；缺少数据时“启动游戏”不可用。
- [ ] 已识别到受支持数据、仅待启动时完整校验的游戏保持正常颜色。检查中不提前标成缺少数据；资源不完整或版本不支持时保留准确的状态说明。
- [ ] 使用已选外部数据目录或合集内目录的实际检查结果；不以固定目录是否存在、运行时是否接入或可选 DLC 是否安装作为置灰依据。
- [ ] 补齐／移除数据、切换数据目录和点击“刷新”后，卡片状态正确更新；不改变既有游戏顺序或上次选择。
- [ ] 在 CN／EN／JP 检查“全部无数据、部分有数据、补齐后刷新”三种界面，覆盖鼠标／键盘选择与导入入口。复用状态检查与绘图缓存，不因置灰增加滚动时的磁盘扫描。

## DLC 启用流程（现有作品）

- [ ] 逐作确认 DLC 内容是否已包含在本体，以及实际启用条件。资源齐全、仅受资格／解锁标志限制的内容，由运行时直接启用；重点检查仅为解锁而依赖额外 key 的模式。
- [ ] DLC 自带独立程序或素材时，沿用原始包识别、自动解包和资源验证。虫姬二原始 STFS 包的自动提取已经存在，复用该路径，不重建一套工具；本项补充解锁处理及实际模式验证。
- [ ] 玩家数据目录和原始资源保持现有布局，准备产物写入既有缓存。消除仅用于内部准备的 header／生成文件要求，补双语数据说明与小型回归。
- [ ] 分别验证仅本体、可直接解锁的内置内容、独立资源包三种情况；检查进关、保存／录像以及重启读回。原作靠游玩获得的进度解锁保持原行为，DLC 缺失不影响本体卡片颜色。

## 阶段一：平台验证与最小运行时

- [ ] 盘点两份镜像：启动 ELF、静态库／符号、IOP IRX、动态装载／覆盖段、VU 程序、图形命令及音频资源。用实际文件确认原作模式、练习、设置、存档和录像能力。
- [ ] 确认重编译工具与运行时的来源、许可和固定提交，补入项目依赖恢复流程，并先通过上述统一工具链的构建检查。运行时与工具本身应可在没有 ROM 的环境构建；游戏代码生成仅使用本地数据。
- [ ] 核对宿主指令集和浮点／MMI 语义，确定最低 CPU 要求；可选向量优化按能力分派，避免把开发机的 AVX 能力写成所有玩家的前提。
- [ ] 以 ESPGaluda 为第一条启动链：`ISO → ELF／资源准备 → 函数分析 → R5900 代码生成 → x64 宿主 → 原作菜单／第一关`。检查间接跳转、异常／系统调用、MMI、FPU／VU0 及动态代码入口。
- [ ] 将缺失函数、系统服务和未实现命令集中汇总，按实际调用链处理。临时返回值仅用于定位，关键读盘／同步／绘图／音频接口要有真实实现。
- [ ] 用两作实际命令确认 GS 实现路线，冻结一个默认后端。优先复用已存在的成熟实现；原生简化路径和兼容路径按兼容性与成本选择，不先重写整套渲染器，也不直接套用 Xenos／GCN 的命令译码。

本阶段交付：固定工具链、可重复的无 ROM 机制检查、首作菜单与实际第一关出画／输入／声音，以及第二作的模块需求清单。先完成这条闭环，再扩展模式和 Ibara。

## 阶段二：完成共用服务和 ESPGaluda

- [ ] **调度与系统。** 实现实际需要的线程、信号量、定时器、中断／VBlank、SIF／RPC、读盘和文件服务；保持原作时间基准，定位轮询后再做事件化，不能随意跳过等待。
- [ ] **镜像读取。** 同时核对按文件和按扇区读取的调用，保留原 LBA、偏移与异步完成语义；准备缓存不能改变游戏依赖的光盘布局。
- [ ] **GS／VU。** 补齐 DMA／VIF／GIF 数据交接、贴图与 CLUT、纹理／帧缓冲重叠、混合与遮罩、显示场／帧、裁切和旋转。按实际使用审查 VU 微程序，不能因其为 2D 游戏就假设不使用 VU。
- [ ] **声音。** 接通 IOP／LIBSD／SPU2 中实际使用的路径、流式 BGM、音效混音和宿主输出，记录队列深度与欠载；SDK 音频不能直接复用 Xbox 360 的 XAudio/XMA 实现。
- [ ] **合集接口。** 复用共用配置和 SDL 设备层，接通 PS2 按键、窗口、音量、焦点处理、正常退出及进程状态。新宿主不另建配置界面。
- [ ] **游玩与保存。** ESPGaluda 的 ARCADE、ARRANGE 是首批玩法；按原作菜单补齐角色、练习和其他入口。核对觉圣切换、护罩／炸弹、计分、死亡／续关、暂停、BGM／音效和模式返回。
- [ ] **持久化。** 实现原作实际使用的记忆卡服务，验证设置／成绩保存和关闭重启读回；如果原作提供录像，继续验证保存、读回和确定性，不先自建另一套录像系统。

ESPGaluda 使用 ARIKA 的移植版本，Ibara 的移植实现不同。可共享平台服务，不假设两作的函数地址、音频驱动、存档或游戏循环相同。

## 阶段三：接入 Ibara

- [ ] 为本作建立独立数据清单、函数映射、代码生成配置和适配文件，复用已验收的 PS2 运行时。
- [ ] 完成 ARCADE、ARRANGE 及原作实际提供的练习／选项入口；核对机体／武器、蓄力炸弹、计分、难度变化、死亡／续关和模式切换。
- [ ] 检查菜单、弹幕／爆炸重叠、透明特效、背景滚动、竖屏和声音压力，补齐本作触达的新 GS／IOP 路径。
- [ ] 验证独立记忆卡数据、设置保存和重启读回。共用层修复补小型回归，避免为 Ibara 改坏 ESPGaluda。

本版先完成原作的单人流程、存档和已有功能。原生联网能力与录像能力在镜像盘点时确认；社区排行榜、自建联网或新增录像作为独立功能决定，不把现有 PS4／360 的协议套到 PS2 原作上。

## 阶段四：帧节拍、延迟与效率

从首作出画时就留下一份固定场景基线，不等到两款接完才开始查性能。

- [ ] 测量实际更新／呈现节拍、CPU 等效核数、GPU 工作、内存、音频队列和长帧来源，区分原作减速与宿主卡顿。保持原作场／帧频率，不为显示几百 FPS 改变游戏速度。
- [ ] 建立无 ROM 的 micro bench，覆盖 GS 包处理、CLUT／纹理缓存、批次提交、同步唤醒和音频混音；保留图像／状态正确性校验，再做多轮优化。
- [ ] 分解 SDL 输入到游戏取样、响应逻辑／绘图、GPU 提交和呈现后段。以现有低延迟路径为目标，不预先把 PS2 标成 1V，也不复用别作未验证的后段数字。
- [ ] 以同机、同数据、同场景和相同输出设置，对比 PCSX2 的 CPU 等效核数、帧节拍和同口径延迟；列出运行时优化前后的收益。先获得一致数据，再更新中英文 README。

## 阶段五：合集和交付

建议新增目录沿用现有分层：

```text
backends/ps2/          共用平台、GS／VU、音频和宿主服务
games/espgaluda/       数据清单、重编译配置及本作适配
games/ibara/           数据清单、重编译配置及本作适配
third_party/ps2/       经核对并固定版本的依赖
runtime/ps2/           两作宿主和共用运行组件
```

- [ ] 新增 `ps2` 后端识别，接入 catalogue、PrepareLaunch、数据导入、配置、构建／整理、认证收据和程序包；保持现有统一启动合同。
- [ ] 增加两张匹配现有风格的 banner，日文原名配英文副标题；按上节统一实现全部作品的数据缺失置灰。
- [ ] 同步中英文 README、数据指南、每游戏 `README.txt`、开发入口与许可清单；新文件名使用英文。
- [ ] 小而完整的实际验收：每作两个主模式代表性进关、至少一个 Boss 场景、练习入口、输入／音画、设置保存与重启读回、模式返回及正常退出；原作存在录像时再覆盖其完整回放。其余菜单按实际清单逐项检查。
- [ ] 针对共享代码补 PS2 机制回归、两作交叉短测和旧后端的小型检查。保持无 ROM 测试可运行；不以一轮游戏测试代替以后可重复的检查。
- [ ] 同一源码提交构建、固定依赖与符号匹配；按现有流程生成不含游戏数据的程序包，一次解压核对清单及用户数据保留。冻结后再走正式发布流程。

## 实施前需要收敛的事项

1. 实际镜像版本、完整性、ELF 和覆盖段：当前尚未盘点，不能固定重编译地址或宣称某版已支持。
2. 共用运行时和 GS 默认后端：由首作最小闭环与两作命令审查决定，不能仅依据其他项目的截图或 FPS 选择。
3. 原作的录像、练习及保存细节：以实际菜单和调用为准，盘点后形成每作清单。
