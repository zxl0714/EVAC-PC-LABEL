# v0.9.0：PS2 运行时与 ESPGaluda

v0.9.0 只支持 PS2《エスプガルーダ / ESPGaluda》。Ibara 本版展示 Coming Soon 卡片，可玩支持留到后续版本；现有镜像、代码、分析与构建缓存保留。完成本版开发、验收和打包后停在正式发布之前。

11 月 3 日调整：v0.9.0 接受当前 ESPGaluda EXE 体积，使用正常 ZIP 压缩发布；完成当前崩溃修复后走发布流程。
代码精简与出包提效纳入下方 v0.9.1 计划。

## v0.9.1：共用 PS2 代码精简与构建提效

- [x] **共用分析工具。** 接入已有 PS2 分析、生成流程，按游戏／模块读取入口和代码范围，统计函数体重叠、内部跳转／恢复入口及重复生成量，输出可比较的报告。ESPGaluda、Ibara 使用同一套工具，由各自配置提供输入。
- [x] **共用生成优化。** 根据控制流和入口语义共享函数体，减少重复机器码及生成文件。保留全部可调用入口、寄存器状态、延迟槽、调度恢复和模块切换语义；不同覆盖模块中相同地址的代码分别处理。转换在分析／生成层完成，不手改生成后的游戏 C++。
- [x] **接入构建与缓存。** 工具沿用项目锁定工具链，输出可重复；生成规则和输入变化能正确使增量缓存失效。先以 ESPGaluda 验证，再使用 Ibara 已有分析输入检查复用，不将 Ibara 的完整游玩支持列为本项验收条件。
- [x] **验证收益及等价性。** 用无 ROM 小夹具覆盖内部入口、间接调用、跳转、恢复及模块同地址情形，再做受影响游戏的小型回归。对比 EXE／PDB 大小、生成文件数量及编译、链接、校验耗时，不预设缩小比例。
- [x] **PDB 随代码去重观察。** 先记录生成代码精简后的符号体积变化，不单列符号精简专项；仍异常膨胀时再定位。匹配符号保留在本地，不放入程序包。
- [x] **出包提效。** 复用一次冻结构建认证，只校验实际入包文件，避免反复扫描未入包的生成源码和 PDB。每份最终 ZIP 保留一次真实解压验收；默认只出程序包。

以下保留 v0.9.0 的验收与测量记录。

## 3. 输入延迟与 PCSX2 对比

- [ ] 沿用 README 的统计口径：平均输入取样等待、原游戏响应与绘图、GPU／呈现后段；设备输入、显示器扫描和面板响应单独说明。
- [ ] 保留分段数据和可复核的响应画面证据，不把 Present 返回或宿主重绘率当作实际输入响应。
- [ ] 与 PCSX2 使用同一台电脑、同一份镜像、相同场景／输出设置，对照取样节拍、响应帧和呈现路径。
  官方 PCSX2 2.8.2 的独立 BOSS 状态已用只读 PINE 内存和逐帧画面交叉核对：
  右移与左移两次都在首步读到新方向、第三步首次呈现对应位移，即输入消费后相隔两个更新；
  不再把之前未标定取样时机的“三次推进”直接当作三帧输入延迟。
  该对照证明游戏响应链的更新数，正常呈现后段与完整毫秒口径继续单列。
- [ ] 延迟若高于模拟器，或在模拟器仍有明显延迟时没有优势，继续定位和优化。
- [ ] 检查 ARCADE／ARRANGE 的实际时序，不能直接套用其他平台的 1V 标签或历史后段数字。
  原始主循环在 VBlank 等待之前读取并映射输入；私有候选将原等待前移，保留一次等待、
  两个输入例程的相邻顺序及原有绘图同步。ARCADE 三个首响应画面对照从 Pad+2 提前到 Pad+1，
  PadRead 至响应画面 Present 返回平均 31.135→16.873 ms；这还不是屏幕显示时间。
  候选 ARRANGE 的选人、进关、觉圣、护罩、暂停／恢复和返回标题短回归已通过，
  音乐生命周期、普通帧时间与完整呈现后段仍需收尾。证据：`late-input-arrange-r2/acceptance.json`。
