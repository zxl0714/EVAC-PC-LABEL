v0.9.0 只支持 PS2《エスプガルーダ / ESPGaluda》。Ibara 本版展示 Coming Soon 卡片，可玩支持留到后续版本；现有镜像、代码、分析与构建缓存保留。完成本版开发、验收和打包后停在正式发布之前。

- [x] 修复画廊加载崩溃：从原始回调表提取全部同类入口，生成真实代码，并在构建前检查完整性。
- [ ] 验证移动、射击、觉圣／护罩、炸弹、死亡／续关、暂停及正常退出。

## 2. 帧时间稳定性

- [ ] 收集第一关、BOSS、弹幕／爆炸及菜单切换的帧间隔，报告中位数、P95、P99、最大值和长帧数量。
- [ ] 目标是消除常规游玩的超过 20 ms 长帧，并继续压到 19 ms 内；逐条追查超过 19 ms 的样本。
- [ ] 分解 EE／IOP 工作、调度与定时等待、GS 排队、前帧 GPU 等待、命令处理和呈现，按证据优化。
- [ ] 使用可重复的离线 workload／micro bench 打磨开销，再用小型实际场景确认音画与帧节拍。
  已有原始 EE 库函数及 SPU 音频 ABBA 基准；声道优化已接入构建，实际游戏回归及 CPU 收益待确认。
- [x] 正常构建关闭重型诊断；测量不带自动按键脉冲、同步 RAM 快照或逐条日志。

## 3. 输入延迟与 PCSX2 对比

- [ ] 沿用 README 的统计口径：平均输入取样等待、原游戏响应与绘图、GPU／呈现后段；设备输入、显示器扫描和面板响应单独说明。
- [ ] 保留分段数据和可复核的响应画面证据，不把 Present 返回或宿主重绘率当作实际输入响应。
- [ ] 与 PCSX2 使用同一台电脑、同一份镜像、相同场景／输出设置，对照取样节拍、响应帧和呈现路径。
- [ ] 延迟若高于模拟器，或在模拟器仍有明显延迟时没有优势，继续定位和优化。
- [ ] 检查 ARCADE／ARRANGE 的实际时序，不能直接套用其他平台的 1V 标签或历史后段数字。

## 4. CPU 效率

- [ ] 实测移植版与 PCSX2 的 CPU ms/s，换算为等效逻辑核数；1 核 = 1000 CPU ms/s。
- [ ] 在相同的代表场景和完整时间窗口比较，记录编译器、模拟器版本、设置及 CPU／GPU 型号。
- [ ] 目标是移植版 CPU 开销低于模拟器；按热点优化，保留优化前后的收益数据。
- [ ] 将延迟与 CPU 的简洁对照表放在中英文 README 的性能区，完整测量方法放入 ANALYSIS。
